## Integration

### SPC

Both locks resolve the same exact SPC 0.2.0. MHFE re-exports its Secret, SecretError, Isolation and native writer, and delegates stack cleanup. The old OS code and shared buffer implementations are removed. The host should enter isolation before reading input or creating native Argon2 threads. This library does not supply terminal input, protected worker execution or separate protected-stack execution.

Isolation::enter uses Options::new, applying the system defaults and reporting what succeeded. File-lock and sendmsg refusal, own-process signals, lock-all-memory, dynamic-code refusal, Microsoft-only DLLs and all-thread Linux filtering are opt-in. Choose compatible strict requirements in the host. Windows process-wide dump suppression is unsupported, while per-page dump exclusions still apply within OS limits. Android follows thread-scoped filtering without Linux TSYNC, macOS memory-read protection depends on hardened signing, and browser/WASI applies no process isolation.

The one production unsafe cast reborrows initialized SPC pages as an exclusive Argon2 Block slice. A real alignment check, exact block size and the live area length bound the cast on 64-bit native targets. The native engine creates four ordinary 2 MiB Rayon stacks and requests SPC clearing after the Argon2 call returns. The area is reused, so between-call wiping remains necessary when SPC also wipes at Drop. A single entire-slice zeroize can remove the second call to the cast and per-block barriers.

### Reed–Solomon

The exact RSC 0.2.0 has its protect feature and resolves the same SPC. MHFE removed its local decoder and field code, and retains parsing, admitted BIP39 counts, erasure ordering, and result checks. The shared algorithm uses GF(2^11), first root 1, step 1 and shortened repair shapes with parity 2, 4, 6 or 8.

Accepted counts, two-byte field values, sorted marks and scratch sizes meet the contracts of the three expect calls. An uncorrectable input returns the documented correction failure. Reconstructed words must pass BIP39 checksum validation. MHFE and RSC request stack clearing from different frame positions. The wiped ranges can overlap. The residual source-level copy in RSC is recorded below.

### AUD-007-SEC001 — The password check stages secret word indices in a stack array on wasm32

- Affected paths. src/password_check.rs:42-48 · src/password_check.rs:82-114 · src/password_check.rs:124-144 · src/stack.rs:12 · SECURITY.md:15-20
- Contract. Password word indices use protected storage or explicitly cleared scratch storage.
- Evidence. Check::of initially uses a Secret. restored_index builds a normal five-element u16 array from that Secret, and check_word accepts a separate by-value array. The dependency does not clear a WebAssembly stack.
- Impact. Secret-derived indices have an unprotected source-level lifetime on wasm32. This review establishes neither a physical spill location nor a path for another origin to read it.
- Fix. Compute the weighted sum from the protected byte pairs without a staging array. Prefer a borrowed index input or an explicit zeroizing owner for an owned argument.
- Verification. Run published password-check profile vectors and review optimized wasm32 cleanup for the touched values.
- Related. AUD-006-SEC001

### AUD-007-SEC002 — The Reed–Solomon tail creates a second copy of secret-derived lane bytes

- Affected paths. src/repair/code.rs:28-68 · reed-solomon-core 0.2.0:src/field/lanes.rs:60-72 · reed-solomon-core 0.2.0:src/cyclic/words.rs:110-120
- Contract. Tail arithmetic avoids by-value copies of explicitly zeroized repair buffers.
- Evidence. CyclicWords encodes two-byte GF(2048) shards with a nonzero factor through the short lane path. zip(made) consumes a copy of the Copy array, then made.zeroize() wipes only the original.
- Impact. The Rust source leaves an additional iterator-owned value without explicit cleanup. The optimized WebAssembly spill and lifetime were not established.
- Fix. Use a borrowed iterator in the shared Reed–Solomon crate, verify the relevant optimized targets, release the dependency, then update MHFE pins together if needed.
- Verification. Run independent public parity and repair vectors with the updated dependency on both wasm32 targets and a native target.
- Related. AUD-006-SEC001

### AUD-007-SEC003 — Secret-derived verifier comparisons do not enforce constant-time work

- Affected paths. src/packing.rs:49-55 · src/wallet_check.rs:114-120 · src/cipher.rs:112,179
- Contract. Comparisons of secret-derived data follow CHECK-SEC-009 and avoid content-dependent short-circuiting.
- Evidence. Packing compares a verifier with ordinary slice equality. The wallet check uses Iterator::all for two digest bytes. The cipher also uses ordinary equality on secret state.
- Impact. Short-circuiting can make work depend on secret data. No usable timing signal or attack was established.
- Fix. Use a reviewed constant-time primitive where secret-derived data is compared and retain the existing public error behavior.
- Verification. Run the public vectors and review generated comparison code on target configurations that differ.

### AUD-007-ARC001 — CI never executes the declared browser-target library in a browser-class engine

- Affected paths. docs/audits/TARGETS.md:24-25 · .github/workflows/ci.yml:170-203 · Cargo.toml:1-20
- Contract. RUST-16 and guide §17 require independent execution evidence for a supported exact target.
- Evidence. CI compiles wasm32-unknown-unknown into a Rust library and tests the distinct wasm32-wasip1 binary in Wasmtime. The target table describes wasm32-unknown-unknown as required.
- Impact. Browser-target linkage, target-specific behavior and coverage depend on a separate consumer harness. WASI and Node evidence have different scope.
- Fix. Link a small browser-target harness calling the library on public vectors and require it to report a non-zero successful count in a pinned Node or browser job.
- Verification. Check the exact wasm32-unknown-unknown artifact, its imports, the pinned engine and the profile-test count.

### AUD-007-ARC002 — The recovery fuzzer misses the failure branches of readings

- Affected paths. fuzz/fuzz_targets/recovery.rs:43-74 · src/cipher.rs:138-158 · src/recovery.rs:104-152
- Contract. The readings fuzz target drives independent supported lengths, rejected lengths and outcomes of the selected suite.
- Evidence. The same untrusted length is passed to decrypt first. If admission rejects it there, readings is never called. Errors returned by readings are ignored and successful results are checked partly against another value from the same recovery object.
- Impact. The target can pass with an implementation that always returns an error. Structured admission cases have weaker coverage than the closure of AUD-006-ARC003 implies.
- Fix. Create recovery with a known admitted setup, vary the readings input independently and assert expected rejects, candidate counts and verification flags from an independent expectation.
- Verification. Show that legal and invalid length branches run. Retain published verified and unverified branch vectors.
- Related. AUD-006-ARC003

### AUD-007-ARC003 — The password-check fuzzer can pass if every input is declared inapplicable

- Affected paths. fuzz/fuzz_targets/password_check.rs:19-35 · tests/profiles.rs:147-179
- Contract. The harness drives valid EFF words as well as malformed strings and verifies positive and negative outcomes.
- Evidence. The harness ignores Fits and NotApplicable, supplies arbitrary UTF-8 without a structured valid-word branch and never calls check_word. The integration tests do exercise public success and erasure.
- Impact. The fuzzer adds robustness evidence for input shapes it hits. Its assertions cannot detect blanket rejection or ensure progress through useful cases.
- Fix. Generate valid public synthetic six-word cases and vary erasure and substitution. Keep raw UTF-8 as a separate path in the same parser target.
- Verification. Use a seeded corpus or fuzzer deterministic branches to show reach of every Check outcome.

### AUD-007-ARC004 — Fuzz targets repeat the same admitted BIP39 entropy lengths and selector

- Affected paths. fuzz/fuzz_targets/phrase.rs:17 · fuzz/fuzz_targets/repair.rs:16 · fuzz/fuzz_targets/recovery.rs:17 · fuzz/fuzz_targets/passphrase.rs:17 · xtask/src/copies.rs:38-39
- Contract. CORE-10 keeps a common test normalization rule in one owner.
- Evidence. Four fuzz harnesses independently define the same five lengths and implement the same shape selector. The copies gate scans only src and xtask/src.
- Impact. Future changes can silently diverge in test input generation even while production accepts one shared set.
- Fix. Share the shape helper inside the fuzz workspace without expanding the production API.
- Verification. Build all six targets and confirm that the distinct parser and round-trip assertions stay in the individual targets.

### AUD-007-ARC005 — The public API gate ignores several valid Rust public item declarations

- Affected paths. xtask/src/public_api.rs:27-40 · xtask/src/public_api.rs:86-94 · xtask/src/public_api.rs:245-298 · docs/public-api.txt:1-6
- Contract. Every public item within the declared top-level inventory is found or rejected by the gate.
- Evidence. The line scanner recognizes a short set of literal forms. A public async function or qualified unsafe extern function does not match. The conditional forms of doc(hidden) and macro_export escape the literal deny scan.
- Impact. The 22-item snapshot is consistent today. The gate can miss a later API change or an excluded public item.
- Fix. Parse public top-level declarations and relevant attributes, or fail closed for an unsupported public declaration rather than silently skipping it.
- Verification. Add gate tests for qualified declarations and cfg_attr. Preserve the documented exclusion of methods and fields.

### AUD-007-ARC006 — The vendored gate accepts an empty digest declaration and an empty directory

### AUD-007-DOC002 — The native integration example discards the outcome of best-effort isolation

- Affected paths. src/lib.rs:34-46 · SECURITY.md:98-125 · secret-protection-core 0.2.0:src/protect.rs:336-379
- Contract. Host examples make a deliberate decision about mandatory protection properties before reading any secret.
- Evidence. The example prints Isolation::enter and then reads a secret even when a protection the host might require is unconfirmed. Production MHFE delegates isolation policy to the host by design.
- Impact. A program copying the example may treat a report as an enforced policy, especially in a multi-threaded host or on a platform that cannot grant a property.
- Fix. Use SPC strict process-wide entry with platform-appropriate requirements in the example, or show an explicit best-effort security decision. Keep process-wide side effects at the host boundary.
- Verification. Compile the revised example and check behavior for missing properties with supported native target evidence.

### AUD-007-DOC003 — The suite and README overstate probabilistic recovery checks

- Affected paths. src/suite.rs:25-30 · src/recovery.rs:135-148 · README.md:57-64 · tests/spec/README.md:454-477
- Contract. Short verifiers are statistical and automatic recovery may yield an unverified 24-word reading. The optional wallet check is only 16 bits.
- Evidence. The public Suite 3 description states that a wrong password is detected. The README also presents the optional check as recognition without qualifying its strength.
- Impact. Hosts can overstate recovery confidence. The verified flag and algorithm produce the specified results.
- Fix. State which reading is unverified and describe both checks as statistical indicators.
- Verification. Compare rustdoc and README text with published recovery branch and profile vectors.

## Evidence limits

- Native unsafe WorkArea Miri coverage. The current native engine replay stops before the cast at an unsupported mmap/mprotect protection mode in locked SPC. Older broader selection stopped at sigfillset. Eight pure checks passed in total, including an s390x repair-generator test.
- Android ARM64, Android x86-64 and iOS device have exact CI link evidence. Android and iOS simulator or device runtime is unverified.
- Native i686 is rejected explicitly by the 64-bit engine contract. The supported 32-bit path is wasm32, tested as WASI and as bare WASM. The s390x portable Miri selection is recorded separately.
- No new full-cost vector replay in this ordinary audit. Public fixture identities and fast branches were checked.
- Historical harness files were inventoried as archive and read where they support active claims. Archived reproductions were not executed.
- The exact hosted job logs do not disclose every kernel or page size. Custom probes actually retained in the CI output are indexed in evidence/ci-exact-custom-probes.json. Physical erasure of every optimized stack or register copy and independent cryptographic certification remain outside this evidence.
