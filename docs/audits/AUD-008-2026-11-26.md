### AUD-008-SEC001 — The README example can print original and recovered mnemonics

- Affected paths. README.md:85-99 · src/recovery.rs:124-151 · src/phrase.rs:373-403
- Contract. An example accepting actual mnemonic values selects the right recovery reading and keeps plaintext out of all error text.
- Evidence. The example takes the first auto-selected reading and calls assert_eq on strs. Suite 3 can list a different short candidate before the intended result, including when decryption succeeded.
- Impact. The panic includes both operands as raw strings and may put both mnemonics in stderr or collection logs for a host modeled on the example.
- Fix. Select the known length and compare without formatting mnemonic contents. Return a redacted error or false. Separate the example’s public self-check from host wallet-check policy.
- Verification. Compile the example and verify it handles multiple lengths without displaying secrets. Use existing public ambiguity fixtures.

### AUD-008-BLD001 — The isolated WASM lockfile diverges and is omitted from RustSec

- Affected paths. wasm/Cargo.lock · wasm/Cargo.toml:28-36 · .github/workflows/audit.yml:8-22 · .github/workflows/audit.yml:39-51
- Contract. Every active lockfile receives advisory screening and cross-target evidence identifies the exact locked dependency graph.
- Evidence. The new WASM graph has ctutils 0.4.8, itoa 1.0.19, sha2 0.11.2 and syn 3.0.10, while the root has ctutils 0.4.6, itoa 1.0.18, sha2 0.11.1 and syn 3.0.9. Root and fuzz graphs agree. CI RustSec still scans only root and fuzz.
- Impact. The successful 28-case bare-WASM run applies to an independently resolved graph. It cannot prove the exact root SHA2 or related compiler dependency on that target.
- Fix. Drive the WASM harness from the root lockfile or keep every shared resolution synchronized and add the WASM lock to all advisory triggers and checks.
- Verification. Check exact versions and digests with the root, then rerun RustSec and the Wasmtime harness.

### AUD-008-ARC001 — Shared fuzz input generation silently discards valid-length constructor errors

- Affected paths. fuzz/src/lib.rs:10-15 · fuzz/fuzz_targets/{phrase,repair,passphrase,recovery}.rs
- Contract. The shape helper skips only raw inputs that cannot supply the selected public length. A refused supported entropy size fails the fuzz assertion.
- Evidence. Phrase::from_entropy on an already admitted size is converted to Option with ok. Four structured fuzz targets discard None, conflating rejected entropy construction with a short fuzzer input.
- Impact. A regression that refuses valid entropy can skip structured cases across all four targets. The shared refactor removed earlier per-target constructor assertions.
- Fix. Handle the input length first and require the constructor to succeed for each of the five admitted counts.
- Verification. Assert that representative public vectors from each admitted length reach the downstream checks.

## Evidence limits

- Five author-reported 60-second fuzz runs on this revision do not satisfy the ordinary five-minute budget. The first-round repair run passed 767747 cases. Other first-round long campaigns were interrupted by laptop thermal constraints or were not run.
- The native WorkArea and its only raw cast are byte-identical to the first snapshot. Miri was previously blocked at the SPC mapping protection mode before the cast. Findings about machine-code timing or physical stack contents remain separate from source evidence.
- Android ARM64 and x86-64 and iOS device linked in exact CI. iOS simulator evidence is Clippy only if verified locally. No Android or iOS runtime is established.
- Exact bare-Wasm run exercises the three profiles on its own locked graph. It leaves full browser host-engine behavior to the consumer and does not establish physical secret clearing.
- The full-cost protocol replay and release-tag package attestation are outside this ordinary audit.
