## Findings

### AUD-011-SEC001 — Low — Historical registry can serve files outside its synthetic fixture directory

- **Scope.** `docs/audits/AUD-002-harnesses/skeptic-bld-republish/src/registry.rs:62`
- **Method.** Static control-flow review of the raw request-to-file path at the committed snapshot. No requests were sent.
- **Expected.** The local fixture service can open only its explicitly served synthetic corpus files.
- **Observed.** Request handling rejects parent components but does not verify that the path is relative and resolves inside the fixture directory before it reads a file.
- **Impact.** On Unix, an unauthenticated same-machine client can reach the temporary listener while the optional historical harness is running and may receive files readable by its process. The library and release package do not contain the listener.
- **Evidence.** The checks and resulting filesystem join in registry.rs were independently traced. The separate build harness is not affected by the same path form.
- **Suggested fix.** Serve an explicit allowlist of fixture paths from owned bytes rather than arbitrary request-mapped filesystem paths.
- **Verification.** Verify ordinary Cargo fixture requests and reject non-allowlisted targets using synthetic fixtures only.

### AUD-011-DOC001 — Low — README assigns the absence of a short reading to a verifier match

- **Scope.** `README.md:60`, `src/recovery.rs:69`, `src/recovery.rs:136`
- **Method.** Read the wrong-password overview against the detected-length decision table and pinned specification.
- **Expected.** Describe the common no-match result separately from the rare chance match.
- **Observed.** The wording attaches no short reading to a chance verifier pass. Recovery returns a matching short reading and labels the verifier match. On zero matches a stated short length is refused, and an unstated length can yield an unverified 24-word reading.
- **Impact.** A reader could misunderstand what a verifier match or a surviving short reading means when recovering a backup. Runtime code and its detailed docs agree with the specification.
- **Evidence.** Three reviewers independently compared the README, source and recovery rules. The suite tests exercise both branches.
- **Suggested fix.** Separate the zero-match and rare-match cases and retain the distinction between a verifier match and wallet identification.
- **Verification.** Cross-check wording against the match, no-match, different-length and ambiguous recovery cases.

## Observations and limitations

- AUD-004-ARC001 already records the narrow historical verification contracts. verify2 uses mtimes and untracked paths, so a deleted tracked path is not checked. Its diff digest is only printed. The old JSON checker compares raw key spelling, so escape-equivalent keys are outside its check. Neither limitation establishes that an old recorded verdict was wrong. The current report uses the complete tracked inventory and decoded-key validation.
- AUD-010 is retained as the uncommitted review of 00c070c. Its command outputs were checked separately from its prose. The cited semver tool skipped all 260 checks on the version transition. Its Miri harness models an aligned cast and does not execute the production WorkArea path. Its code generation log records compilation. These results are not stronger evidence of semantic compatibility or optimizer behavior.
- password_check::Check and repair::Change return words deliberately requested by their callers. The output ownership boundary in SECURITY.md applies to those values. No extra hidden payload leak was established by this review.
- Only the optional historical registry uses the affected listener. Its sibling build harness strips all leading Unix separators, so the same absolute-path issue does not apply there.
- The specification test submodule is a pinned input. Relevant protocol text, manifests and public vectors are reconciled at the gitlink. The rest of that separate repository is not a second audit scope.
- Ordinary audit of mhfe_core. No full-cost Argon2 vector replay, publish action, tagged package or attestation verification for 0.3.0. The full-cost test remained ignored by the fast suites.
- Miri reaches nine syscall-free tests in each retained aliasing run. Native Secret construction hits unsupported libc::sigfillset. The isolated cast model cannot establish the production allocator path. No all-target timing or complete memory-residue proof.
- The mobile rows are compilation evidence only, and the iOS simulator has no native execution. Bare WebAssembly runs in Wasmtime. A browser application, its CSP and its engine are separate scopes.
- Upstream protection and Reed–Solomon code were reviewed at the exact pinned integration boundaries. Pinned dependency hashes and tests are not a complete audit of those repositories.
- The 28 historical harness lockfiles received source/cache integrity review where archives existed. Fresh RustSec coverage is scoped to the three active unchanged lockfiles.
- Historical harness source was reviewed, preserving its original evidence and inputs. Historical probes that use obsolete checkouts, external processes, credentials, or mutable caches were not started.
- The 96.84 percent coverage is retained from the documented 1fe8761 measurement. Its log and row totals were reconciled, and the final commit changes documentation only. The run does not have an independent contemporaneous input hash.
- The exact CI does not execute a RustSec workflow because dependencies did not change. All three active manifests, locks and the audit workflow are byte-identical to the passing RustSec snapshot. Neither that result nor archive hashes exclude future advisories.
- Report status reflects confirmed defects in required checks. The new findings are Low and non-blocking individually, and none demonstrates a break in production encryption or recovery.
- Three five-minute attempts completed before the local limit changed. Recovery was interrupted and contributes only its last observed counter. Repair and password_check ran with a hard 30-second process cap. Missing hosted extended fuzz, corpus minimization and coverage remain explicit gaps.
