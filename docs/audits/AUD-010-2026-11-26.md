[section 17.5 of the guide](../../../.github/audits/FULL_AUDIT_GUIDE_V2.md#175-evidence-per-target-and-the-release-decision):

   `00c070ce20fdf7dc4d0ffaba9c1f8a9f07ae4b72`, and every required native and WebAssembly row linked

   `cargo test --locked --workspace --release` locally, `wasm/` in V8 locally, and all 13 jobs of
   GitHub Actions CI run `45859679641`).

   - **Target:** `x86_64-unknown-linux-gnu`, fuzzing (`phrase`, `password`, `passphrase`,
     `recovery`, `repair`, `password_check`). **Missing check:** 300 seconds per target under
     `nightly-2026-11-13` and AddressSanitizer as specified in `docs/audits/TARGETS.md` for an
     ordinary audit (30.99 to 37.99 active seconds per target ran locally with 1,635,317
     executions and zero crashes). **How to obtain it:** run
     `cargo +nightly-2026-11-13 fuzz run <target> -- -max_total_time=300` for all six targets on a

     `docs/audits/AUD-010-harnesses/audit-probes` passed under both `-Zmiri-strict-provenance` and

## Review evidence

### Scope and methodology

- **Crates and tools:** root library `mhfe-core` (`0.3.0`, unpublished), repository task runner
  `xtask`, bare-WebAssembly verification crate `wasm/` (`mhfe-core-wasm-checks`), fuzz workspace
  `fuzz/` (`mhfe-core-fuzz`, six libFuzzer targets), build gate `build.rs`, all integration suites
  under `tests/`, GitHub Actions workflows (`.github/workflows/{ci,audit,vectors,release}.yml`), and
  repository documentation (`README.md`, `SECURITY.md`, `CHANGELOG.md`, `THIRD_PARTY_NOTICES.md`,
  `AGENTS.md`, `docs/**`).
- **Cryptographic and protocol surface:** MHFE specification `v0.7.0` (`tests/spec` at `4535e3d`),
  suites 3 (`MHFE3-R12-ARGON2ID-SHA256`) and 4 (`MHFE4-R12-ARGON2ID-SHA512`), 12-round unbalanced
  Feistel network over `132..=264` bits, BIP39 English lookup and constant-time entropy/checksum
  packing, Unicode 18.0.0 NFKD passphrase normalization, check-word generation/verification, wallet
  fingerprint derivation (`HMAC-SHA512("Bitcoin seed")` -> `secp256k1` compressed public key ->
  `HASH160` first 4 bytes), password token check, and `GF(2^11)` Reed-Solomon card parity/repair
  (`k in {2, 4, 6, 8}`).
- **Pinned security-critical upstream crates inspected from cached source:**
  `reed-solomon-core =0.2.0` (`crates.io` archive matching upstream `74c8053`) and
  `secret-protection-core =0.2.0`, plus `argon2 0.6.0`, `bip39 2.2.2`, `bitcoin_hashes 0.20.0`,
  `cmov 0.5.4`, `ctutils 0.4.8`, `rayon-core 1.13.0`, `secp256k1 0.31.1`, `sha2 0.11.2`,
  `unicode-normalization 0.2.0`, and `zeroize 1.9.2`.
- **Host environment:** Linux 7.0.0 x86-64, `rustc 1.99.1`, MSRV `rustc 1.99.0`,
  `nightly-2026-11-13` (Miri and `cargo-fuzz 0.13.2` with AddressSanitizer), `cargo-llvm-cov 0.8.5`,
  `cargo-audit 0.22.1` (`1,575` advisories), `cargo-deny 0.19.0`, `cargo-semver-checks 0.47.0`,
  `dprint 0.63.0`, and Node.js `v26.12.1` (V8 WebAssembly engine).
- **Exclusions:** full-cost Argon2id vector replay (`tests/full_cost.rs`, covered on demand via
  `vectors.yml`), 300-second per-target fuzzing (31 to 38 active seconds per target ran locally),
  Miri past `secret-protection-core`'s `sigfillset` boundary, and runtime execution on Android/iOS
  devices or emulators.

#### Architecture and code-rules gate (`ARC`)

##### AUD-010-ARC001 — Low — `xtask` Cargo manifest version gate skips TOML dependency sub-tables, commented headers, multiline

- **Category:** ARC.
- **Severity:** low.
- **Status:** open.
- **Release blocking:** false; all four active `Cargo.toml` manifests in `00c070c` comply with
  `CORE-25`, so this defect affects gate enforcement on future manifest edits rather than shipped
  library behaviour.
- **Affected files and builds:** `xtask/src/code_rules.rs:515-568` (`check_cargo_requirements` and
  `cargo_dependency`), invoked by `cargo xtask code-rules` and `cargo xtask check`.
- **Reproduction:** run
  `CARGO_TARGET_DIR=target/aud-010-harnesses cargo test --locked --manifest-path docs/audits/AUD-010-harnesses/audit-probes/Cargo.toml`,
  which calls `code_rules::run` directly on a synthetic manifest containing
  `[dependencies.subtable-wildcard]\nversion = "*"`,
  `[dependencies] # inline comment\ncommented-wildcard = "*"`, and a multiline inline dependency
  table `multiline-wildcard = {\n  version = "*"\n}`.
- **Expected behavior:** `cargo xtask code-rules` enforces `CORE-25` (exact `=x.y.z` pins in
  non-published workspace manifests, no wildcard requirements) across every valid Cargo TOML
  dependency declaration form.
- **Observed behavior:** `check_cargo_requirements` sets
  `in_dependencies = line.ends_with("dependencies]")` whenever a trimmed line starts with `'['`, and
  inspects single lines with `cargo_dependency`. Strip-comment handling does not run on section
  headers, `[dependencies.<pkg>]` / `[target.'cfg(...)'.dependencies.<pkg>]` headers do not end with
  `"dependencies]"`, and multiline `{ ... }` inline tables split the crate key from `version = ...`,
  so all three forms pass `code_rules::run` without error while a single-line `plain-wildcard = "*"`
  fails with `CORE-25` as expected.
- **Impact:** a future dependency added via TOML sub-table syntax, under a commented `[dependencies]`
  header, or formatted across multiple lines bypasses automatic `CORE-25` version-pinning checks in
  CI. Current manifests are unaffected.
- **Evidence:** `docs/audits/AUD-010-harnesses/audit-probes/src/main.rs:195-261`;
  `AUD-010-evidence/harness-run.log` (`fcd5d5f8...`) and `AUD-010-evidence/harness-test.log`
  (`4f5a2d87...`).
- **Recommended fix:** strip `#` comments (outside quotes) before inspecting TOML headers, recognize
  `[dependencies.<name>]`, `[dev-dependencies.<name>]`, `[build-dependencies.<name>]` and target
  equivalents (extracting `version` within that sub-table, or rejecting dependency sub-tables in
  favour of canonical single-line entries), and accumulate `{ ... }` inline tables until the closing
  `}` before checking `version`.
- **Required verification:** unit tests in `xtask/src/code_rules.rs` covering sub-table dependencies,
  headers with trailing `#` comments, multiline inline dependency tables, and workspace/git/path
  specs without `version`, followed by `cargo xtask check`.
